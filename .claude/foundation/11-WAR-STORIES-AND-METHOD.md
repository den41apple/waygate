## Урок 1: диагностируй реальное состояние, а не «view»

**История (потерян ~день):** на Ubuntu 24.04 + Docker 28+ агент применял правила через `iptables`,
рапортовал «applied=1, errors=[]», но трафик не маршрутизировался. Полдня ушло на ложные гипотезы
(conntrack stale, Yandex Security Group, rp_filter, Docker FORWARD drops).

**Корень:** `iptables` указывал на **legacy** alternative. Правила уходили в legacy-модуль, который
Docker 28+ отключает. `iptables -L` показывал их (**shadow-chain** через iptables-nft compat), но
реальный netfilter-hook их не видел.

**Диагностика-якорь:**
```bash
sudo update-alternatives --query iptables | grep Value   # должно быть iptables-nft
sudo iptables -t mangle -S PREROUTING                     # view (compat)
sudo nft list chain ip mangle PREROUTING                  # реальное состояние ядра
# расходятся → shadow-chain
```
**Урок:** сравнивай то, что «команда показывает», с тем, что **реально в ядре/системе**. Чинить —
`update-alternatives --set iptables iptables-nft` (провижионер делает это автоматически, см. `05`).
Тесты тоже должны читать реальное состояние (`nft list`, а не `iptables -L`), иначе зелёное ложное (`08`).

## Урок 2: прорисуй полный путь ДО правки reactive-кода

**История:** целый день в reactive-режиме (правка → проверка → правка) по routing-проблеме, потому
что не была нарисована **полная траектория пакета** через netfilter-hooks для разных случаев
(forwarded vs local-originated vs incoming-на-local). Решение пришло, только когда путь прорисовали
целиком — и стало видно, что mark в FORWARD/OUTPUT принципиально не сработает.

**Урок (обобщённо):** перед изменением системы с нетривиальным потоком (пакеты, данные, события,
стейт-машина) — **нарисуй полный путь от входа до выхода для всех значимых случаев**. Один день
рисования экономит несколько дней реактивного тыка. Зафиксируй вывод в `.claude/*.md`.

## Урок 3: toolchain-first и не убивать долгие операции

**История (эта сессия):** задача стопорилась дважды. (1) На машине **вообще не было Node/npm**
(только адобовский `node.exe`) — а половина задачи требовала npm. (2) Установку Playwright-браузера
несколько раз **прерывали, убивая node-процессы** для «проверить статус» → каждая прерванная закачка
оставляла битую папку → `Executable doesn't exist`.

**Уроки:**
- **Проверь тулчейн в самом начале** (`node -v && npm -v && uv --version`). Не предполагай, что он есть.
- На win PATH не подхватывается в новой сессии shell-инструмента — префиксь `$env:Path`.
- **Долгую установку/закачку не убивай** ради «посмотреть прогресс». Дай ей завершиться (придёт
  нотификация). `Select-Object -Last N` в PowerShell **буферизит** весь вывод до конца — отсутствие
  прогресса ≠ зависание.

## Урок 4: Claude Design — две сущности и кто что запускает

**История:** хотели «залить дизайн фронта в Claude Design и крутить там». Споткнулись на путанице.

**Уроки (если будешь делать дизайн-синк в новом проекте):**
- **Design (прототип) ≠ Design System.** Промпт-генерация UI — это **Design**. `/design-sync` пишет
  **только** в **Design System** (библиотека компонентов). Тип проекта неизменяем при создании.
- **`/design-sync` — user-triggered** (как ultrareview): Claude Code сам запустить **не может**, жмёт
  пользователь в CLI после `/design-login`. Модель может всё остальное (scaffold, компоненты, stories)
  + работать с DesignSync read/write-tool как фолбэк-конвертер.
- **Storybook ставить с первого дня**, компоненты — **presentational-first** (рендерятся на пропсах,
  без хуков данных). Тогда stories тривиальны и синк безболезнен. В доноре компоненты сцеплены с
  хуками → пришлось городить seed-декоратор с предзаполненным QueryClient — не повторяй.
- Конвертер рендерит stories в headless-браузере → нужен Playwright-браузер (см. урок 3).

## Урок 5: идемпотентность + честная отчётность = самовосстановление

Любой `apply` — read→diff→remove-orphans→add-missing, повтор безопасен (`04`). Счётчик
`applied/skipped/errors` — **честный** (считать реально изменённое). Персистить `last-apply.json` →
healthcheck сам перезапустит apply при errors. **Никогда не патчить состояние инкрементально** — только
полный reconcile. Это убирает целый класс «прошлый запуск оставил хвост» багов.

## Урок 6: дисциплина источников истины

- **Один источник истины для контракта** (Pydantic/enum) → всё генерится, дрейф в CI (`07`).
- **Один источник истины для конфигов/юнитов** (`importlib.resources`, не инлайн-строки) (`05`).
- **Frozen-snapshot data-migrations** (сырой SQL, без ORM) — миграция переживёт переименования (`02`).
- **Архитектурные решения и грабли — в `.claude/*.md`**, а не в головах. Этот набор — продолжение
  той же практики. При входе в подсистему сначала читай её doc, а не гадай.

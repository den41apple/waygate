# Сессия 2026-05-06 — root-cause forwarded трафика на Ubuntu 24.04

## TL;DR

Проблема из SESSION_2026_05_04 (forwarded трафик с phone не выходит из VM)
**решена**. Корень — Docker 28+ на Ubuntu 24.04 управляет nftables напрямую,
а `iptables` команды попадают в shadow-chain без интеграции с реальным
hook'ом. Решение — писать через `nft` напрямую.

## Что сделано

### Test-AWG-server (`scripts/setup-test-awg-server.sh`)

- Обновлён под полные AWG 2.0 параметры из `AWG_PARAMS.txt`:
  S3/S4, I2-I5, H1-H4 как range'ы (`665634046-1180630982`).
- Параметры вынесены в переменные `AWG_*` — server и client рендерятся из
  одного источника, handshake-симметрия гарантирована структурно.
- Коммит `6498347`.

### Установка amneziawg-tools на target VM

- `amneziawg-tools 1.0.20210914-0~202602231231+5d6179a` (свежий билд от
  2026-02-23 несмотря на старый base-номер) переустановлен из `ppa:amnezia/ppa`.
- DKMS-модуль `amneziawg-1.0.0` тоже свежий (март 2026).
- AWG 2.0 параметры (S3/S4, I2-I5, H-ranges) парсятся корректно.

### Диагностика (8 шагов LOG-маркеров)

1. Сначала — гипотеза stale conntrack. `conntrack -F` дал 0 deleted,
   отпало.
2. tcpdump — пакеты от phone доходят до eth0, но MASQ-rule не срабатывает.
3. Поставили `LOG`-target в filter.FORWARD, mangle.POSTROUTING, nat.POSTROUTING.
4. После теста с phone — в `dmesg` появилось 124+ `WG-FWDIN` (filter.FORWARD
   шёл), но `WG-MNGPOST` и `WG-NATPOST` — **0 пакетов**.
5. Вывод `nft list ruleset` показал что **`chain ip filter FORWARD` имеет
   policy drop**, и наша iptables-rule в нём отсутствует — она в теневой
   chain от iptables-nft-compat.
6. `nft insert rule ip filter FORWARD iifname/oifname "awg-test-srv" counter
   accept` — пакеты пошли, transfer стал симметричным, MASQ counter растёт.

## Дополнение: системный fix apply-flow (вторая половина дня)

После ручного fix'а test-AWG-server'а через `nft insert rule ...` пользователь
включил direction "ВСЁ" в waygate UI. Apply упал с **новой** ошибкой —
`apply_rules: [host/v4] apply all-internet-v4: ip exited with 1: Cannot find
device "awg-eurohoster"`. Race в агенте: `redeploy_with_network_mode` →
`docker run -d` возвращает control до того как awg-quick внутри контейнера
поднимет iface → последующий `ip rule add ... iif awg-X` падает. Любые
повторные нажатия Apply ничего не дают — agent log молчит, idempotent reconcile
считает что "всё применено" (хотя ipset'ы созданы, но MASQ/ip rule не
применились).

### Что сделано (план — `~/.claude/plans/fizzy-sprouting-rabbit.md`)

**Phase A — agent**
- `agent/awg_clients.py`: `_wait_for_iface(iface, timeout_s)` — поллит
  `ip -o link show <iface>` после `docker run -d`, до 10с (configurable
  через `settings.awg_iface_wait_seconds`). Закрывает race.
- `agent/routing.py`: `_retry_netns_switch` — резерв поверх wait, retry x2 с
  backoff 0.5s на случай если `redeploy_with_network_mode` всё-таки не
  дождался.
- `agent/routing.py`: `_persist_apply_attempt` / `_load_last_apply` —
  `/var/lib/waygate-agent/last-apply.json` хранит результат последнего apply
  (timestamp, count, errors, succeeded).
- `agent/main.py`: `last_applied_rules_count = response.applied` (а не
  `sum(... if enabled)`); `AgentState` расширен `last_apply_errors` и
  `last_apply_succeeded`.
- `shared/schemas.py`: `AgentStatus` получил `last_apply_errors: list[str]`
  и `last_apply_succeeded: bool` с defaults для back-compat.

**Phase B — server**
- `server/api/_apply_helper.py` (новый): извлечён `run_full_apply` из
  `api/rules.py`. Используется и из HTTP endpoint'а, и из healthcheck для
  auto-reapply.
- `server/tasks/healthcheck.py`: `_auto_reapply_if_needed` — при
  OFFLINE→ONLINE с `last_apply_succeeded=False` или непустыми
  `last_apply_errors` server **сам** триггерит full apply, без явного
  нажатия пользователем. Throttle 60s per-server против flapping.

**Phase C — tests**
- `agent/tests/test_integration.py`: 4 переписанных теста с `iptables -S`
  на `nft list chain ip <table> <chain>` (закрывает NFT-1 — тесты теперь
  ловят shadow-chain bug на Ubuntu 24.04 + Docker 28+). Добавлен `_nft_dump`
  helper. К `test_apply_rules_writes_real_state` дописан assert на
  MASQUERADE в `nat POSTROUTING` (раньше эту проверку никто не делал).
- 3 новых integration-теста: `test_apply_recovers_after_iface_appears_late`
  (Phase A1+A2 покрытие), `test_status_reports_apply_errors` (Phase A4),
  `test_no_orphan_ip_rule_after_failed_apply_then_empty` (regression на
  сегодняшний leftover `fwmark 0x3 lookup 102`).
- `agent/tests/test_awg_clients.py`: 2 unit-теста на `_wait_for_iface`
  (polls until visible / timeout raises).
- `server/tests/test_healthcheck.py`: 3 unit-теста на auto-reapply
  (срабатывает при errors[], не срабатывает при succeeded=True, throttle
  дедуплицирует <60s).
- `agent/Dockerfile`: добавлен `nftables` пакет (отдельным RUN после
  docker-ce-cli чтобы cache первого apt-install не invalidate'ился).

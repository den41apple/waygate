# Сессия 2026-05-06 — root-cause forwarded трафика на Ubuntu 24.04

## TL;DR

Проблема из SESSION_2026_05_04 (forwarded трафик с phone не выходит из VM)
**решена**. Корень — Docker 28+ на Ubuntu 24.04 управляет nftables напрямую,
а `iptables` команды попадают в shadow-chain без интеграции с реальным
hook'ом. Решение — писать через `nft` напрямую.

## Что сделано

### Test-AWG-server (`scripts/setup-test-awg-server.sh`)

- Обновлён под полные AWG 2.0 параметры из `AWG_PARAMS.txt`:
  S3/S4, I2-I5, H1-H4 как range'ы (`665634046-1180630982`).
- Параметры вынесены в переменные `AWG_*` — server и client рендерятся из
  одного источника, handshake-симметрия гарантирована структурно.
- Коммит `6498347`.

### Установка amneziawg-tools на target VM

- `amneziawg-tools 1.0.20210914-0~202602231231+5d6179a` (свежий билд от
  2026-02-23 несмотря на старый base-номер) переустановлен из `ppa:amnezia/ppa`.
- DKMS-модуль `amneziawg-1.0.0` тоже свежий (март 2026).
- AWG 2.0 параметры (S3/S4, I2-I5, H-ranges) парсятся корректно.

### Диагностика (8 шагов LOG-маркеров)

1. Сначала — гипотеза stale conntrack. `conntrack -F` дал 0 deleted,
   отпало.
2. tcpdump — пакеты от phone доходят до eth0, но MASQ-rule не срабатывает.
3. Поставили `LOG`-target в filter.FORWARD, mangle.POSTROUTING, nat.POSTROUTING.
4. После теста с phone — в `dmesg` появилось 124+ `WG-FWDIN` (filter.FORWARD
   шёл), но `WG-MNGPOST` и `WG-NATPOST` — **0 пакетов**.
5. Вывод `nft list ruleset` показал что **`chain ip filter FORWARD` имеет
   policy drop**, и наша iptables-rule в нём отсутствует — она в теневой
   chain от iptables-nft-compat.
6. `nft insert rule ip filter FORWARD iifname/oifname "awg-test-srv" counter
   accept` — пакеты пошли, transfer стал симметричным, MASQ counter растёт.

## Открытые follow-up'ы

### Высокий приоритет

1. **Проверить waygate-agent на Ubuntu 24.04 + Docker 28+.** У нас есть
   свидетельство что `awg-firstbyte` MASQUERADE счётчик растёт в реальной
   nft-chain (значит NAT через iptables работает). Но FORWARD ACCEPT — не
   проверен. Если scope=host direction не работает на свежей Ubuntu —
   нужно мигрировать `agent/routing.py` на `nft` команды. Тестово
   попробовать применить direction со scope=host на нашей VM сейчас и
   проверить, доходит ли трафик до eurohoster.

2. **Переписать `setup-test-awg-server.sh` на `nft`.** PostUp/PostDown
   сейчас через `iptables`, на Ubuntu 24.04 без ручного fix'а скрипт
   создаёт **broken** state (handshake есть, трафик не идёт). Это
   воспроизводимо в любой fresh VM.

### Средний приоритет

3. **`amnezia-awg2` контейнер на VM** — после наших изменений (nft FORWARD
   accept для awg-test-srv) старый VPN через amnezia-awg2 "почти не
   работает". Скорее всего это **independent issue** (eurohoster-канал
   внутри контейнера протух, в шаге 7d ещё ДО изменений был timeout).
   Вариант — `docker restart amnezia-awg2` или снос (его конфиги/ключи
   только в Dockerfile-volume на host'е, при `docker rm` всё пропадёт —
   нужен `awg showconf` бэкап).

## Где остановились — open issue

### Проблема: forwarded трафик с телефона не работает на yandex VM

**Topology:**
- Telephone подключается к AmneziaWG-server-контейнеру `amnezia-awg2`
  (запущен через приложение AmneziaVPN, **`--network bridge`**, listen UDP/42014).
- Test-AWG-server (поднят `scripts/setup-test-awg-server.sh` с I1-параметром,
  host netns, listen UDP/52000) — handshake проходит ✓.
- Direction "all-internet → eurohoster" со scope=host через AWG-client
  `waygate-amnezia-client-eurohoster` (`--network host`, host netns).

**Симптом:**
- Phone подключается к test-AWG-server: handshake свежий, transfer
  `34 KiB received, 580 B sent` (асимметрия!).
- В FORWARD chain `awg-test-srv → *: 282 packets ACCEPT`. То есть pkt'ы от
  phone уходят в forward.
- `MASQUERADE -s 10.99.0.0/24 ! -d 10.99.0.0/24: 0 packets`. Наше SNAT
  правило **не срабатывает**.
- На eth0 yandex VM `tcpdump -n host 1.1.1.1` = **0 packets**. Pkt'ы вообще
  не выходят из VM.
- На phone в браузере `https://1.1.1.1` не открывается → handshake есть,
  data — нет.

**Гипотезы для следующей сессии:**

1. **Docker FORWARD-rules дропают** трафик из не-docker iface на eth0.
   Проверить:
   ```
   sudo iptables -L DOCKER-USER -v -n
   sudo iptables -L DOCKER-FORWARD -v -n
   ```
   Если в DOCKER-FORWARD есть DROP for non-docker iface → нужно добавить
   ACCEPT в DOCKER-USER для нашего awg-test-srv:
   ```
   sudo iptables -I DOCKER-USER 1 -i awg-test-srv -j ACCEPT
   sudo iptables -I DOCKER-USER 1 -o awg-test-srv -j ACCEPT
   ```

2. **Yandex Cloud Security Group** блокирует egress от приватных src
   (10.99.0.x). Проверить настройки SG в yandex.cloud Console — есть ли
   `Outbound any/any allow`.

3. **rp_filter strict** на каком-то iface — drop'ает pkt с src=10.99.0.2.
   Хотя ранее `net.ipv4.conf.all.rp_filter = 2` (loose).

4. **conntrack zone mismatch** — bridge-mode amnezia-awg2 живёт в одной
   conntrack-zone, host netns в другой, awg-test-srv в host netns. Trafic
   chained через две зоны может терять state.

### Что точно работает

- `--interface awg-eurohoster` curl от хоста → **82 Мбит/с** (eurohoster baseline).
- Handshake test-AWG-server ↔ phone.
- iface awg-test-srv поднят, kernel-mode AmneziaWG.
- Direction со scope=host применяется (mangle/rule/route/MASQUERADE на
  awg-eurohoster — всё на месте).
- Локальный curl с самого VM через mark-routing → **3.5 Гбит/с** до cachefly
  (eth0 baseline) когда direction выключен.

### Что НЕ удалось протестировать

- **scope=container на amnezia-awg2** с eurohoster — это второй вариант
  обхода bridge-NAT-проблемы. Не успели до конца отладить, но в начале
  сессии получали 14 Мбит/с (тогда был firstbyte = медленный provider).
  С eurohoster через scope=container ожидание ~30-50 Мбит/с.

### Что точно НЕ делать в следующей сессии

См. конец `ROUTING_ARCHITECTURE.md`. Кратко:
- Не маркировать в FORWARD chain (mark после route lookup'а — counter растёт,
  reroute не происходит).
- Не маркировать local-originated в OUTPUT (socket-bind mismatch).
- Не использовать catch-all без `addrtype LOCAL` bypass'а.
- Не запускать AWG-server в `--network bridge` для scope=host (двойной NAT).
